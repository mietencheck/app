# Repository guidance

- Find and apply repository guidance relevant to the current task. Read linked documents only when their stated scope applies.
- During normal work, identify durable conventions, recurring corrections, and non-obvious context worth preserving. Do not record temporary task details, obvious advice, or unsupported assumptions.
- When guidance needs adding, correcting, removing, or reorganizing, proactively propose the exact changes and briefly explain their value. Obtain user consent before editing repository guidance or documentation. Explicitly requested documentation changes already provide consent.
- Keep guidance concise and avoid duplication. Prefer links to representative code over copied examples.
- When a topic warrants a separate document, propose moving it and leaving a short “read when” link here. Create documents only when they have useful content.
